# 벤치마크 갱신

노션에 모아둔 「반응 터진 스레드 글」을 읽어서, 스레드 글 생성기가 보는
참고 자료를 최신으로 맞춘다.

## 노션 페이지

```
https://app.notion.com/p/3cf716819fd881fd96a8d4bdf01bb45b
제목: 🔮 사주 글 벤치마킹 (루월당 배포용)
```

`notion-fetch` 로 읽는다. 페이지는 계속 늘어나므로 **매번 새로 읽는다.**
캐시된 내용이나 이전 대화 기억으로 대신하지 않는다.

## 손대는 파일 — 이 둘은 항상 같이 간다

| 파일 | 무엇 |
|---|---|
| `services/threads/BENCHMARK.md` | 생성기 프롬프트에 그대로 들어가는 참고 자료 |
| `services/threads/copycheck.js` | 베낀 글을 걸러내는 검사. **소재 목록**이 여기 있다 |

⚠️ **BENCHMARK.md 에 원문을 새로 넣으면 `copycheck.js` 의 `topics` 에도
그 소재를 넣어야 한다.** 안 그러면 방금 넣은 원문을 모델이 그대로 베껴 쓰고,
검사는 그걸 못 잡는다. 이 둘이 어긋나는 것이 이 작업에서 가장 흔한 사고다.

## 순서

### 1. 노션을 읽는다

`notion-fetch` 로 위 페이지를 가져온다. 확인할 것:

- 유형이 늘었는가 (지금은 인사·무료사주 / 사주 내용 / 댓글 유도 셋)
- 대표 글이 늘었는가 — 인용(`>`)으로 적힌 원문
- 「통하는 방식」 표가 바뀌었는가
- 「세 줄 요약」이 바뀌었는가
- 지표(조회·좋아요·댓글)가 갱신됐는가

캡쳐 이미지만 있고 글자가 없는 항목은 **본문에 넣지 않는다.**
스타일 분석에 쓸 수 있는 건 글자로 옮겨진 원문뿐이다.
사장님이 사진 속 글도 넣기를 원하면 그때 사진을 읽어 옮긴다.

### 2. BENCHMARK.md 를 고친다

**기존 구조를 지킨다.** 통째로 새로 쓰지 말고 바뀐 데만 손본다.

```
# 실제로 터진 글 — 유형과 공식
  (베끼지 말라는 경고)
## 먼저 — 숫자가 말해주는 것
## 유형 ① 인사 · 무료사주글
   ### 네 단계로 짜여 있습니다
   ### 뜯어본 글        ← 원문은 인용(>)으로
## 유형 ② 사주 내용글
## 유형 ③ 댓글 유도글
## 이 자료를 쓰는 법     ← 맨 아래 「쓰인 소재」 목록
```

지킬 것:

- **원문은 인용(`>`)으로 적는다.** `copycheck.js` 가 인용줄만 원문으로 읽는다.
  인용이 아니면 베끼기 검사에서 빠진다.
- 분석은 **「왜 통했는지」 한두 줄**로. 길게 쓰면 프롬프트만 무거워진다.
- 계정 아이디(@…)는 넣지 않아도 된다. 짜임새가 중요하지 누가 썼는지는 아니다.
- 파일이 너무 길어지면 프롬프트 값이 오른다. **유형당 대표 글 2~3편**이면 충분하다.
  글이 많이 쌓였으면 오래된 것·지표가 낮은 것을 빼고 새 것으로 바꾼다.

### 3. copycheck.js 의 소재 목록을 맞춘다

`refs()` 안의 `topics` 배열. BENCHMARK.md 원문에 나온 **특징적인 소재**를 넣는다.

```js
{ key: '먹는거좋아', why: '「먹는 거 좋아한다=병화일간」' },
```

- `key` 는 **공백·문장부호를 뺀 글자**로 적는다. 검사가 그렇게 다듬어 견준다.
- 너무 흔한 말(`사주`, `일간`, `연애운`)은 넣지 않는다. 멀쩡한 글까지 걸린다.
- 그 원문에서만 나오는 **짝**을 잡는다 — 「현침살+저주」, 「인천 남동구」처럼.
- 빠진 원문이 있으면 `topics` 에서도 뺀다.

### 4. 검사한다

```bash
node --check services/threads/copycheck.js
node --check services/threads/prompt.js
```

그리고 **반드시** 아래 두 가지를 직접 돌려서 확인한다.

**① 새로 넣은 원문이 걸리는가**
BENCHMARK.md 에 새로 넣은 원문을 그대로 `copied()` 에 넣어 본다. 걸려야 한다.

**② 멀쩡한 글이 안 걸리는가**
짜임새만 빌린 새 글 서너 편을 넣어 본다. 통과해야 한다.
여기서 걸리면 `topics` 에 너무 흔한 말을 넣은 것이다.

```js
const cc = require('./services/threads/copycheck');
cc.copied('여기에 글');   // null 이면 통과, 객체면 걸림
```

**③ 프롬프트에 실리는가**

```js
const { loadBenchmark, buildPrompt } = require('./services/threads/prompt');
loadBenchmark().length;              // 0 이면 파일을 못 읽은 것
buildPrompt('도화살', {}).length;    // 프롬프트 전체 길이
```

프롬프트가 **15,000자를 넘으면** 벤치마크를 줄인다. 매 생성마다 나가는 값이다.

### 5. 사장님께 알린다

- 무엇이 늘고 무엇이 빠졌는지
- 프롬프트 길이가 얼마나 변했는지 (요금과 직결)
- 새 소재를 몇 개 막았는지

커밋은 **확인받고** 한다. 먼저 하지 않는다.

## 하지 말 것

- **`CONTENT-GUIDELINE.md` 를 건드리지 않는다.** 그건 「어떻게 쓸까」이고
  벤치마크는 「이렇게 쓰니 터지더라」다. 역할이 다르다.
- 노션에 있는 분석 문장을 그대로 옮기지 않는다. 이 파일은 **모델이 읽는 지시문**이라
  「~합니다」체 설명보다 「~한다」체 규칙이 낫다.
- 베끼기 검사 기준(`GRAM`, `RATIO_LIMIT`)을 함부로 낮추지 않는다.
  낮추면 베낀 글이 통과한다. 멀쩡한 글이 자꾸 걸리면 기준이 아니라
  `topics` 에 넣은 말이 너무 흔한 것이다.
